# API 共通仕様

---

## エラーレスポンス形式

すべてのエラーレスポンスは以下の形式で返す。

```json
{
  "message": "エラーの概要",
  "errors": [
    { "field": "フィールド名", "message": "フィールドごとのエラーメッセージ" }
  ]
}
```

| フィールド | 型 | 説明 |
|---|---|---|
| `message` | string | エラーの概要メッセージ。常に含まれる |
| `errors` | array | フィールドごとのエラー詳細。バリデーションエラー（400）・コンフリクト（409）のみ含まれる |

> `errors` はフィールド単位のエラーが存在する場合のみ含まれる。認証失敗（401）・タイムアウト（408）などは `message` のみ返す。

---

## 401 Unauthorized — 未認証

認証が必要なエンドポイントに未ログイン状態でアクセスした場合に返す。

```json
{
  "message": "認証が必要です"
}
```

---

## 403 Forbidden — CSRFトークン不正

`POST` / `PUT` / `PATCH` / `DELETE` の全エンドポイントは、二重送信Cookie方式によるCSRFトークン検証を必須とする。

リクエスト時は `csrf_token` クッキーの値を `X-CSRF-Token` リクエストヘッダーに付与する必要がある。クッキーが存在しない、またはクッキーの値とヘッダーの値が一致しない場合は以下を返す。

```json
{
  "message": "CSRFトークンが不正です"
}
```

このエラーはレスポンスヘッダー `X-CSRF-Error: 1` を伴う（権限不足などクッキー起因でない403と区別するため）。クライアントは `GET /api/csrf` を呼び出すことで新しい `csrf_token` クッキーを取得できる。
